# Account audit tabs and local time controls

The audit UI exposes System activity, Memory reads & writes, Connections, and Sign-in & security. Each tab sends `group=system|memory|connections|security` and the same exact action/outcome and inclusive UTC time filters used by export. Grouped queries reject legacy `source` and nonzero `offset`. The opaque `cursor` encodes only the consumed offsets of the two streams; it does not grant access or contain account identity. Every request derives the owner from the session, queries Core by user ID and Identity by account ID, and revalidates the session after awaiting Core. Filter each stream before paging, order by timestamp/source/ID, then return at most `limit` rows plus the next cursor. Existing `source=core|identity` callers remain supported. Listing/export are bounded live reads, not immutable snapshots: concurrent writes can move offset positions, and export deduplicates by source and audit ID. A refresh restarts listing at the current cursor; a filter change starts at the beginning.

The explicit action lists live in `shared/console-queries.mjs`. Both `connection.*` and `connections.*` events are covered. Unknown actions remain in account-scoped System activity with an unclassified marker. This does not add event collection, reconstruct missing history, expose null-owner events, or make global service logs visible. System activity does not promise complete operational logging.

Memory IDs remain recorded references. Titles are computed from currently owner-readable memory metadata; they are not historical title/content snapshots. Main rows hide long IDs, which remain selectable and copyable inside Event details. Missing, foreign and lifecycle-deleted memories have no title/link. Search references describe bounded lexical subqueries, not final search results or individually opened memories. No memory body, raw query, credential secret or unfiltered metadata is exported.

Date fields accept local `YYYY-MM-DD HH:mm` text and show the browser's IANA timezone. The calendar uses the existing theme, a native modal dialog for focus containment, roving day focus, arrow/Home/End/PageUp/PageDown navigation, Enter/Space selection, and Escape cancellation. Its draft is only copied to the input by Use this time; filtering occurs only on Apply filters. Clear remains a draft until committed. Backdrop, close and cancel discard the draft. Invalid dates, DST gaps and reversed ranges are rejected; repeated DST times use the earlier occurrence. UTC conversion happens once when applying filters, and UTC URL values render back as local input values.

Validation uses synthetic disposable two-account services and isolated Chromium, including 1440px desktop, 390px phone and 320px narrow phone in Chinese and English. No production data or external model is required. Run Node 24 unit/API tests plus `scripts/test-console-audit.mjs` with the Playwright/Chromium paths and an evidence directory outside the source tree.

The top header contains only language and account controls with matching dimensions, border, typography, hover/expanded states and visible keyboard focus. There is no header search link/form or cross-page search keyboard navigation. Slash and Ctrl/Cmd+K only focus an existing page search field and never intercept editable fields or IME composition. The existing library search API and lexical default remain unchanged; semantic/hybrid controls retain their pre-existing behavior and authorization.
