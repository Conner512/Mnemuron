# 记忆抽取、压缩、向量化与图谱边界

这些改进沿用现有原文、版本、来源引用、账户权限和处理授权，不替换记忆数据库，也不自动开启任何模型服务。页面上的“已保存”“已整理”“已索引”是不同状态；模型或后端失败不能把中间状态显示为完成。

## 抽取：先保留原意和准确标识符

- 显式标签抽取跳过 Markdown 代码围栏中的示例，包括反引号、波浪线及不同长度的围栏。文档里的“事实：……”不应仅因标签格式就变成用户事实。
- 已明确启用的会话抽取保留版本、IP、域名、小数等标识符内部的英文句点。不同完整版本不能先被截成同一前缀，再被误判为重复记忆。
- 精确来源片段和偏移仍指向不可变的源事件；不重新表述事实，不抹去用户/助手来源差异，也不扩大跨项目、会话或账户的去重范围。

## 关键词：模型建议需要自身来源支持

自动“补全关键词”只接受出现在该条记忆原文里的名称，允许格式层面的大小写、Unicode 兼容形式和空白归一，但不会把版本、地址或工程标识符的局部前缀当成完整名称。中文无空格正文中的名称可以匹配。

另一条记忆出现的名称不能借给当前记录；模型臆造的别名、翻译名或关键词会使该任务进入 `review_required`，诊断码为 `INVALID_SOURCE_SET`。整个批次通过校验后才发布，不会只写入有效的前半批。没有可提取名称时，空关键词列表是有效结果。

这是自动补全的限制，不是人工标签的限制：用户或写入 Agent 显式提供的跨语言标签、已有类型和强度保持不变。关键词共现也不代表两个人、设备或项目是同一实体。

## 压缩：完整请求预算与不截断的组批

摘要仍然是**有来源依据的抽取式压缩**，不是自动生成新的事实陈述。本地校验原文片段、顺序和来源版本，并要求模型保留限定条件；长来源的语义完整性仍需质量评估及人工核对。短原子记忆保留完整内容，原始记忆和历史版本不被摘要覆盖。

Organizer 的输入检查覆盖实际发送的完整请求：系统指令、来源、输出 schema、协议包装，以及可能的修复指令。超限请求在预留调用次数之前拒绝，不再因客户端未发送的过大请求消耗调用预算。

Worker 以完整请求的预算为准缩小批次，而不是只按记录数切分。单个来源能放入时，会拆成多个有持久进度的批次；不会截短原文来凑预算。单个来源仍超限时，明确进入待检查状态，需要调整获准的模型配置或源记录，不能伪称压缩成功。已完成批次的恢复、租约、来源版本校验及总预算约束仍然生效。

这里的 token 边界采用 UTF-8 字节数作保守上界，不是假称精确掌握所有模型的 tokenizer，也不等于模型服务的实际计费 token 数。真实压缩质量仍需用固定样本和人工核对评估，参见 [质量评估](memory-first-v0.1/QUALITY.md)。

## 向量：完整分片、可恢复进度与文档级候选

- 分片和装批同时考虑文档前缀、JSON/协议包装、单次条数和输入预算；不会切断 Unicode 字符，也不会漏掉尾部内容。
- 后端确认成功的分块进度持久化。恢复时必须匹配原 generation、模型、账户、记忆、版本、状态摘要、作用域和精确分块布局；只有完全相同的源与布局才可复用。调整模型输入预算而改变分块边界时，不能沿用原来同序号的另一段向量。
- 中间文档和新远端 point 均保持 `building`；所有块完成并通过来源及租约复核后，按账户、文档和构建摘要精确发布远端 `active` 状态，最后才将本地文档标为 `indexed`。预算耗尽或中途失败不会把部分结果当成完整索引，也不会从第一块重复计算已经确认的同源进度。
- 远端写入成功但响应丢失时，采用确定性 point ID 重试，保持幂等；未收到成功确认的写入不能保证免于重复模型调用或远端计费。若全部分块已确认、仅发布响应丢失，恢复只重试幂等发布，不重复嵌入。
- Qdrant 使用文档级分组候选，保留每条文档最佳匹配块，避免一篇长记忆的许多块占满候选窗口。现有 owner、scope、profile 过滤和 SQLite 当前来源校验继续执行。
- 未发布分块不会参与搜索；遇到旧的、未映射的活动 point 挡住同文档有效结果时，复用同一查询向量，有限次排除失效 point 后重查。仍不能得到可信候选时明确降级，不能把后端不一致伪装成成功的空结果。
- 对账清理和写入使用同 generation 的租约互斥，避免清理程序在远端写入与本地进度确认之间误删正在写入的分块。
- 候选窗口有上限；达到窗口边界时明确返回截断状态，不把有限窗口声称成全库完整召回。相似度阈值与混合检索的事实来源边界不改变。

协议针对仓库使用的 Qdrant 1.19 合同，参见 [官方分组查询](https://api.qdrant.tech/v-1-19-x/api-reference/search/query-points-groups) 和 [payload 更新](https://api.qdrant.tech/v-1-19-x/api-reference/points/set-payload)。本地模拟向量和协议测试证明的是代码行为，不能代替真实模型语义相关性、真实 Qdrant 或现网吞吐验收。

## 图谱：全库筛选，有限且可解释的展示

概览图继续是“记忆—关键词/主题/类型”的共现视图，而不是未经确认的实体身份图谱。连线表示返回样本里共同出现的关键词；不据此合并原文或身份。

`GET /v1/console/attention` 和同域 BFF 的对应读取支持：

| 参数 | 范围和语义 |
| --- | --- |
| `graph_days` | 默认 `30`；`0` 为全部，`1`–`3650` 为近 N 个 UTC 日期，依据记忆或标签的最新活动日期 |
| `graph_kinds` | 逗号分隔的 `fact,preference,workflow,architecture,bug,pattern,none`；不传为全部，`none` 表示未标注 |
| `graph_query` | 最多 200 个 Unicode 字符，仅匹配关键词或主题；大小写、兼容 Unicode 和空白归一，不读取正文作图谱搜索 |

账户归属、活动状态、项目生命周期、时间、类型和搜索条件均在返回条数/字节限制之前应用。老记忆刚完成关键词补全后，不会仅因创建时间较旧而漏出近期窗口。

图上的同一关键词、记忆库关键词计数、精确关键词筛选及向量候选过滤使用相同的 Unicode/空白/大小写归一规则。点击节点进入记忆库时，不会漏掉全角或规范等价的写法；一个记忆中的等价重复标签只计一次。精确关键词筛选仍区别 `PVE` 与 `PVE-2`，不会升级成前缀匹配或自动别名合并。

图谱仍只返回 `id/kind/concepts/topic/day`，不携带记忆正文。旧客户端的 `entities` 和 `links` 保持空数组。新增元数据：

- `scope`：实际采用的天数、类型、查询、时间依据和快照时间。
- `active_total` / `active_with_concepts`：本账户所有有效活动记忆及有关键词的数量，供流水线使用，不把图谱样本当成全库计数。
- `kind_counts`：时间和搜索条件下各类型数量，暂时隐藏的类型仍可恢复。
- `filtered_total` / `returned`：满足条件的总量与此次实际返回量。
- `truncated` / `truncation_reason`：是否因 `record_limit` 或 `response_budget` 未全部返回；未截断时原因是 `null`。

单次最多返回 1000 条，图谱 JSON 不超过 180 KiB，给 BFF 的 256 KiB 响应上限留出计数等开销。预算不足时省略整条记录并提示，不截断标签或生成无效 JSON。缩小时间、类型或关键词范围可查看被大窗口挤出的相关记录。

大量记录聚合显示时，没有进入热门关键词或主题的记忆仍保留可访问入口。桌面和手机都能看到样本/截断状态；节点列表可用键盘访问，节点详情与画布缩放后的选择保持一致。读取失败保留上一次有效图并标明筛选尚未应用，允许重试；过时回复不能覆盖新筛选或其他账户的页面。

## 验证与上线边界

回归使用一次性数据库、合成账户/来源、loopback HTTP 和模拟模型。主要入口：

```bash
npm run test:all
npm run test:memory-quality
node --test server/test/memory-traits.test.mjs server/test/console-memory-graph.test.mjs
```

浏览器回归沿用仓库固定版本的 Playwright，覆盖真实 Core/BFF 页面、桌面/手机、双语、失败重试及迟到回复。证据写到仓库外，不发布运行时数据库、账户材料或个人记忆。

图谱模块新增静态资源 `/assets/memory-map.mjs`。使用严格路径白名单的反向代理或 Cloudflare Tunnel 时，部署前需同步 [Console ingress 示例](console-ingress.example.yml) 中的该路径；否则浏览器会因模块请求被拦而无法加载控制台。本次代码变更不会修改现网 Tunnel。

升级不会自动重跑历史提取、改写已有标签、切换模型、建立新索引或扩大模型外发权限。旧数据修复/回填应使用已获准且有明确预算的处理流程；部署、真实模型调用、真实向量后端验收和 PR 合并仍是独立操作。`production_ready` 保持 `false`。
