# Mnemuron 核心优化验收矩阵

> 对应 `CORE_OPTIMIZATION_PLAN.md`。本文件包含 97 个**待实现/执行的验收场景**，不表示测试已经存在或已经通过。
> 每个场景应关联实际测试名、执行命令与结果。可复用已有测试，但必须明确覆盖的是哪项断言。

## 1. 测试环境与数据约定

所有测试使用临时文件数据库、合成事件和回环 HTTP 地址；涉及并发/重启的场景使用真实临时文件而非仅 `:memory:`。清理仅针对测试创建的目录，不拼接用户输入到递归删除命令。

固定时钟、可注入的随机源和本地假服务器用于 TTL、退避、超时测试，不等待真实分钟级间隔。故障注入只存在于测试包装/可注入依赖，不增加生产 HTTP 故障入口。

### 基础 fixture

建议将共同构造放到 `server/test/fixtures/` 或现有测试 helper。实体 ID 是唯一的合成标识；不同用户不要复用相同 Task/Project 主键，避免主键碰撞掩盖用户边界测试。

| 对象 | 示例 |
|---|---|
| 用户 U1/U2 | `user-coretest-a`、`user-coretest-b` |
| U1 Agent A/B | 两个不同 agent_instance_id，独立凭证，共享 U1 |
| U2 Agent C | 归属 U2 的独立凭证 |
| U1 Project A/B | `project-alpha`、`project-beta` |
| U1 Task A/B | `task-alpha-upgrade` 属 A；`task-beta-upgrade` 属 B |
| 分支 | A 下两个 canonical 分支及一个由合法事件观察到的 observed 分支 |
| 会话 | S1、S2；S1 在合法确认后可从 Task A 切换 Task B |
| 用户级记忆 | “输出操作步骤时附带验证命令。” |
| A 项目级记忆 | “升级决定：当前维持 CUCM 旧版本。” |
| B 项目级记忆 | “升级决定：已经确认升级 CUCM 新版本。” |
| A 任务级记忆 | “升级验证使用标识 alpha-exact-restore-2026。” |
| 设备标识样例 | `C9800-CL`、`17.9.8`、`17.98`、`FDO1234ABCD`、`FDO1234ABCE`、`192.0.2.10` |

以上仅作合成场景，不是真实客户数据或技术建议。

### 通用断言

- 不只断言 HTTP 状态。还要断言结果 ID、范围、实体数量、来源、生命周期、审计和副作用。
- 对业务只读测试，比对 Memory/Task/Resume/Receipt/Scope 等业务状态；认证时间和访问审计可变化。
- “未出现禁止项”适用于结果、冲突 variants、摘要、详情和未经授权的计数信息。
- 每项故障测试都检查磁盘/数据库实际状态，不能只看返回的 success/failed 文本。

| S-06 | Task A 加合法 Workstream 子集 | 只保留该 Task 的所选分支及既有共享规则允许项 |

| S-10 | Session S1 合法先后切换两个 Task | 新旧事件来源保留；没有“Session 永久只能属一个 Task”的错误限制 |
| S-11 | user/project scope 保存时带一致的活动 Task/Session 上下文字段 | 合法附加来源不被一律拒绝；scope 不被自动改成 task/session |
| S-12 | 同主题冲突中混入另一个项目和 U2 记录 | 返回的冲突 variants、摘要、计数都遵守当前用户与业务范围 |

## 4. V：核心验证（CORE-OPT-02）

| ID | 操作 | 必须成立的断言 |
|---|---|---|
| V-01 | Store/REST 输入 null、数组、字符串 body | 可预期 400/ValidationError，不 TypeError 500、不写入 |

| V-05 | 有效 Task 但提供错误 Project；提供不可见对象 | 前者拒绝组合，后者不泄漏；全部入口一致 |
| V-06 | 无任何项目/任务的 user scope 保存 | 正常成功，不强制为个人偏好创建虚假项目 |
| V-07 | 直接绕过 Adapter 调 REST/Store 写非法组合 | 核心验证仍生效，不依赖工具 inputSchema |
| V-08 | 在 payload 中伪造其他 user_id/agent_id/证据等级 | 不能覆盖认证身份或提高证据等级；不生成假 Event |
| V-09 | 使用旧版 Adapter 的正常记忆 payload | 兼容调用正常；没有被本轮误改成必须审批或必须有 operation_id |
| V-10 | 首次合法 Session 尚无中心事件；以及历史歧义记录读取 | 合法首次操作不被要求先造事件；歧义历史不被自动猜归属或清除 |

## 5. I：幂等与原子性（CORE-OPT-03）

| ID | 操作 | 必须成立的断言 |
|---|---|---|
| I-01 | 同一主体、同键、同正文和目标连续调用 100 次 | 一个 Memory、一个创建业务审计、同一 memory_id；重放标识明确 |
| I-02 | 同键但修改正文/目标/topic/类型之一 | 每种实际影响意图的差异均 409，原行不变 |
| I-03 | 相同内容但两个不同操作键/不同 Workstream | 不自动语义合并，两个独立意图/来源保留 |
| I-04 | 不提供操作键的旧调用 | 兼容成功；报告不宣称此路径具备重试去重保证 |
| I-05 | 两独立连接/子进程同时提交同键同意图 | 唯一约束和事务保证只有一次写入；竞争方可重放而非重复创建 |
| I-06 | 两连接同键不同意图竞争 | 恰有一个意图获胜，另一方冲突；没有半条实体或部分审计 |
| I-07 | 在实体插入后注入审计失败/幂等记录失败 | 实体、审计、幂等和索引投影一并回滚 |
| I-08 | 数据库提交成功后，假服务器丢弃响应；客户端重试 | 返回第一次 memory_id，不再次写入 |
| I-09 | 同一 Agent 实例换钥后带原键重试；旧钥也尝试重试 | 新有效凭证重放同一操作；旧钥 401 |
| I-10 | 不同用户或不同 Agent 实例使用相同字符串键 | 命名空间隔离，不能拿到对方缓存结果或阻止对方合法操作 |
| I-11 | 首次保存后修订/撤回，再重试原保存操作 | 不复活旧 active，不新建替代；明确当前生命周期与原操作引用 |
| I-12 | 请求头键/body键冲突；对象字段顺序改变；Adapter 网络重试 | 键冲突拒绝；仅字段顺序不同可重放；同一次网络重试保持原键 |

## 6. R：召回、索引与查询安全（CORE-OPT-04）

| ID | 操作 | 必须成立的断言 |
|---|---|---|
| R-01 | A 保存旧精确目标，B 后插入 600 条新噪声，再查 Task A | A 目标仍命中，不被全用户最近窗口挤出 |
| R-02 | 同一个 Task 旧精确目标之后再插 600 条新噪声 | 旧目标仍命中；证明不是只将 Project 条件推到 LIMIT 前 |
| R-03 | 无项目条件，多个项目共 1200 条噪声中查精确标识 | 当前用户的目标仍命中，结果有正确项目来源 |
| R-04 | 查询“语音”“许可”和单字诊断样例 | 对其选择的短词策略有预期命中/明确行为，不因 trigram 默认限制全为空 |
| R-05 | 查询 `C9800-CL`、版本/IP/两条仅尾字符不同的 SN | 精确标识目标命中并优先；相似标识不被称为精确相同 |
| R-06 | 混合中文、英文大小写、全角、Emoji | 索引/查询归一规则一致；存储正文未被修改 |
| R-07 | 查询包含引号、OR、NOT、冒号、括号、百分号、下划线 | 按字面查询合同执行；不 SQL/FTS 注入、不扩大用户范围、不异常 500 |
| R-08 | 精确目标与多个弱相关新记录同时存在 | 精确路径不被单纯 recency 或 BM25 排序方向错误压下 |
| R-09 | 迁移旧库并回填索引，再重复迁移 | 旧记录可检索；原始行摘要不变；索引条目无重复 |
| R-10 | 分别经显式保存、Checkpoint 派生、修订替代等实际路径写入 | 所有相关路径及时可检索，不只 saveMemory 有索引 |
| R-11 | 撤回/修订后立刻检索当前事实，并显式查历史 | 默认不返回已撤回/已替代项；显式历史可见且有状态 |
| R-12 | 删除测试库索引/模拟回填中断，然后重建 | 仅索引可重建；业务数据不丢；未完成索引不能标 ready |
| R-13 | FTS 不可用或索引不健康 | 安全完整扫描降级或明确 SEARCH_UNAVAILABLE/incomplete；不能悄悄查最近500再报告无记忆 |
| R-14 | 相关候选超过500、结果超过20、冲突变体超过预算 | 独立声明候选/结果/冲突截断；不伪造全库精确总数或全库无冲突 |
| R-15 | 长查询/大量词项/扫描预算耗尽 | 资源有界；服务仍响应；不丢失 incomplete/degraded 信息 |

## 8. Q：队列、网络与回执（CORE-OPT-06）

| ID | 操作 | 必须成立的断言 |
|---|---|---|
| Q-01 | 离线提交，进程退出，再启动后恢复网络 | 原业务包、事件/操作ID保留；恢复同步不丢失不重复创建 |
| Q-02 | lane A有明确永久坏项，lane B均正常 | A坏项保留隔离，依赖项有gap状态；B可继续 |
| Q-03 | 401/403 后多次调flush，随后换成有效凭证 | 队列暂停而非删除；不紧密重试；恢复后继续 |
| Q-04 | 429附Retry-After，分别采用delta-seconds及HTTP-date | 正确解析并持久化；重启不提前重试；日期无效则安全退避 |
| Q-05 | 503/429/401返回HTML而非JSON | 状态码仍被保留并按对应策略处理，不全变成永久 invalid JSON |
| Q-06 | 连接重置、总超时、一直滴流的响应、超大响应 | 总时间/内存边界生效，待处理项仍在，错误分类可诊断 |
| Q-07 | 413及带明确首方错误码的400/422坏包 | 保留原始包和原因、隔离可见；不能假报成功 |
| Q-08 | 未知400/404、JSON解析错误、重定向到其他主机 | 进入配置/协议阻塞诊断；不批量清队列、不外送Authorization |
| Q-09 | 固定随机源和fake clock运行多次重试 | attempt_count/next_retry_at持久且符合退避；无真实长sleep |
| Q-10 | delivered/acknowledged/failed回执收到不匹配的2xx正文 | 不mark ACK、不删除唯一证据，进入对账所需状态 |
| Q-11 | 收到409，分别模拟可证实的相同操作与真正冲突 | 仅有精确证据时按既有幂等合同处理；其他保留并阻塞对账 |
| Q-12 | 两进程同时flush同一个队列项；持锁进程死亡 | 不能重复消费导致错误副作用；活锁不被随意抢，死锁可恢复 |
| Q-13 | 服务端已接受，本地删除前崩溃；ACK日志写后重启 | 重放安全、终态准确，不重复注入上下文或把另一Receipt标成已确认 |
| Q-14 | sidecar损坏、队列高水位、缺少Session的旧项 | 保留原包和诊断；旧项保守lane；不清空目录、不静默丢最老事件 |

## 11. E：迁移、端到端与发布门（CORE-OPT-09）

| ID | 操作 | 必须成立的断言 |
|---|---|---|
| E-01 | 老schema合成数据库做增量迁移并重复执行 | 原有列逐行哈希、ID、来源链及行数保持；只增加预期结构/投影 |
