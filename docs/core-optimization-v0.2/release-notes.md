## 验证与复跑

Node 24.19.0 和 26.7.0 分别通过 165 项 Node 测试；两次完整运行中的 23 项 Python 测试也全部通过，零失败、零跳过。97 是方案场景数量，与测试函数数量不是同一口径。

在包含 Git 基线 `4289bfe883d514d0534e9dad000efe70040363f8` 的完整检出目录运行：

```bash
npm test
node scripts/benchmark-core-memory.mjs
```

测试只使用临时数据库、合成凭证和回环服务。迁移回归从基线提交读取旧实现，不能用缺少 Git 历史的源码 ZIP 替代。`npm test` 的 Node 部分失败会阻止后续 Python 执行；需要单独核实时运行 `npm run test:hermes`。

基准覆盖独立的 10,000/100,000 条合成记忆和 30 个固定查询（含 expected/forbidden IDs）。在 Apple M4、16 GiB、macOS arm64 的两套运行时上，Recall@5/10 均为 1、MRR 为 0.98333、越界命中为 0；热读 p95 为 0.229～0.339 ms。全库高频词查询在 100k 档实际耗时 66.737～79.750 ms，仍会占用同步 SQLite 的主线程。

这些是固定字面检索集合的实测，不承诺通用语义召回，也不等于目标服务器容量、私有 TLS 或长期稳定性验收。运行前阈值、测量方式及限制见[检索方案](retrieval-decision.md)。原始运行日志和逐次验收报告保留在私有归档中；复跑产生的证据默认被 Git 忽略。

## 兼容与迁移注意事项

- 无 `operation_id` 的旧保存仍兼容，但没有幂等去重保证；没有新增 Memory 自动发送队列。
- 检索先做权限与业务范围过滤，再取最多 500 个相关候选；候选、正文和冲突预算都有截断标志，不把有界结果伪装为全库完整结果。
- FTS5 不可用时返回明确的 `SEARCH_UNAVAILABLE`，不退回最近窗口。索引是可重建投影，不是权威数据。
- 新增 `GET /v1/memories/:id`，仍需读权限；跨用户不可见，历史内容需显式请求。
- 状态查询不再偷偷发送队列或物理清理 Raw。同步由原有 Hook/同步入口执行；未知本地队列状态不等于零。
- 认证失败、限流、协议错误与永久坏项区别处理。隔离原始载荷和依赖缺口保留，不自动跳过；只有精确接收证明匹配后才移除待发送载荷。
- 单批最多 100 次网络尝试，15 秒后不启动新请求；最后一个已启动请求仍受其自身总期限约束，并非整批硬上限 15 秒。
- 维护分批执行，Raw 到期不删除长期 Memory/Checkpoint 或幂等键。换钥失败时，撤旧/发新/审计事务回滚；认证不缓存撤销或到期结果。
- 数据库迁移是增量式。旧写进程缺少新索引触发器所需函数，禁止新旧程序并行写同一库；旧备份也不包含备份后的新写入。上线与回滚必须保护新增记录，不能直接用旧代码或旧备份覆盖现库。
