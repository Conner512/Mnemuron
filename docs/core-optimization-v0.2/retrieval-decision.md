# 检索方案与冻结基准（Core Optimization v0.2）

## 方案

保留 SQLite，不新增服务或依赖。采用 FTS5 + 显式 doc_id 投影：英文及工程标识整词、中文 unigram/bigram、Unicode 符号；NFKC/小写只用于索引。用户文本转换为十六进制词项，MATCH 不接受用户查询语法。先限定用户、业务范围、生命周期、类型，再从全部合法匹配中选 500 个候选。字面完整短语优先，FTS rank 升序；最终仍使用来源、范围、时间的既有重排。

FTS 是可重建投影，不是权威记录。SQL 触发器覆盖所有 Memory 写入路径，和实体事务一起提交/回滚。启动校验内容/token 与 FTS 完整性，不用行数相等替代校验。不可用时明确 503 SEARCH_UNAVAILABLE，不退回最近 500 条。文档主键在重建中保留。

参照 [SQLite FTS5 官方文档](https://www.sqlite.org/fts5.html) 的 external-content、rebuild、integrity-check 和 rank 合同。未采用 trigram 的原因是本任务必须覆盖一到两个中文字符。

## 运行前冻结的测量合同

- 数据规模：独立 10,000 和 100,000 条合成 Memory；禁止读取正式数据库。
- 固定 30 个检索案例：每例有 query、明确 Task、expected_ids、forbidden_ids；包含短中文、单字、型号、相近版本/SN、IP、NFKC、大小写、Emoji、带引号及逻辑词的字面输入。
- 验收：expected 至少一项进入 top 20，全部 forbidden 不出现；至少一条旧精确记录必须 top 1。固定 ID/数据生成规则，不根据结果修改期望。
- 合成基准目标：10k warm p95 ≤ 250 ms，100k warm p95 ≤ 750 ms；并发请求不得超过 5 秒。实际结果必须在目标运行环境中测量，不等于部署容量验收。
- 首轮：数据库 reopen 后第一遍；不是清空操作系统缓存的物理冷读。单列 reopen/索引校验时间。
- 热读：同一固定集合重复 3 遍。报告 p50/p95/max、响应最大字节数、RSS、数据库/索引大小。
- 额外最坏频词：全规模记录匹配同一 common token，检查候选截断和有界响应，记录耗时；不把有界候选称为全库无冲突。
- 混合负载：loopback HTTP，4 个并发客户端，总计 40 次查询和 10 次真实 saveMemory，记录各类 p50/p95、最大延时、event-loop delay。写入不可覆盖 benchmark 原始 ID。
- benchmark 原始 JSON 为实际测量，不预填结果，不调整阈值以粉饰失败。

## 边界

本版是字面词法检索，不承诺语义等价、任意英文子串或 LLM 事实核验。候选和冲突覆盖有显式预算；长查询超过 64 词项直接拒绝。同步 SQLite 的最坏频词排序仍消耗主线程；报告其实际阻塞时间，不宣称流式并行搜索。

旧二进制不能与新程序并行写启用索引的库：旧连接没有索引 UDF，触发器会拒绝旧写入。关闭新索引读取只会返回可识别的 unavailable，不会启用不安全旧查询。回退旧备份会丢失备份后写入，必须保留并对账增量；不能将旧版范围漏洞称为安全回滚。
